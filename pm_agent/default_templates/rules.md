# 공통 작성 규칙

모든 이슈 유형에 적용한다. 유형별 양식은 같은 폴더의 다른 파일에 있다.
이 폴더의 파일만 고치면 도구가 쓰는 양식이 바뀐다. 위 설정 값은 도구가 제목을 검사할 때도 쓴다.

## 제목

- 한 가지 일만, 40자 안팎
- 모양: 대상 + 할 일 (`모집 결과 화면 구현`). 버그는 보이는 증상 (`나가기 버튼 무반응`)
- 원인과 해결 방법은 제목에 넣지 않는다
- 줄표(—), 가운뎃점(·), `+`, 내부 코드명, 버전 표기를 쓰지 않는다
- `[전투]` 같은 영역 머리말은 버그에만 붙인다. 머리말 목록은 위 `bug_title_prefixes`

## 설명

- 개조식으로 짧게 쓴다. "~함", "~필요", 명사로 끝내도 된다
- 회의록에 없는 정보(담당, 기한, 수치, 원인, 재현 절차)는 지어내지 않는다. 모르는 칸은 통째로 뺀다
- 사람 이름 대신 직군명(개발, 기획, 아트, 사운드)을 쓴다
- 번역투를 피한다: "~을 통해" → "~으로", "~하기 위해" → "~하려고"
- 굵은 글씨는 설명 하나에 한 번까지
- 회의록 근거와 링크는 도구가 이슈를 만들 때 붙이므로 설명에 쓰지 않는다
